# Additive schema 2 migration

Copy learner-state.md and add Sessions/Current.md and Sessions/Questions.md only if absent. Include these new files in custom-edit checks. Keep the old version until all updates reconcile. Never fetch main as a fallback when updating an experimental release: use its exact version tag.

If setup-obsidian is installed, run its `scripts/state.py migrate VAULT` after backing up to a scratch copy and reviewing the dry-run output (`--dry-run`). It adds only missing lesson properties; existing bytes are retained. It refuses malformed or duplicate YAML properties and symlinks. Without the helper, follow the same additive process manually. Do not reserialize learner bodies or normalize line endings. Infer repair only from learning + nonempty last_reviewed/next_review + interval 3; flag this as a migration inference in the report because legacy records cannot distinguish every historical case. A learning note without that evidence remains ordinary learning. Old solid records retain their status, with retention unmeasured; do not invent delayed evidence.

The helper requires Python with PyYAML; use an isolated environment if installation is authorized, otherwise migrate manually. Run `python scripts/state.py check VAULT` from the setup-obsidian skill folder after migration to resolve legacy links and report unknown references, structurally blocked dependencies and the current ready frontier. A blocked report may include downstream dependents, not just cycle members.

Migrate IDs before resolving links/groups. Existing simple prerequisite lists remain AND. Never convert names into guessed IDs. Preserve unknown references as blocked until resolved. On rerun retain all allocated IDs. If interrupted, rerun and reconcile pending operations. Only then advance Template version after rules/templates/dashboard/custom edits have been merged. The helper does not overwrite rules or templates, upgrade installed skills, or claim the whole vault update is complete.

The helper preserves original bytes by inserting properties before the YAML closing delimiter, including CRLF and Unicode. It rejects duplicate keys instead of normalizing them. It validates all lesson files before writes; each replacement is atomic, but the vault update is not a multi-file transaction. Hash checks detect observed concurrent changes; arbitrary editor writes racing after the final check cannot be excluded. Use one writer and a scratch backup.
